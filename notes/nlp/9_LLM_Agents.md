# 9. LLM Agents (LLM 에이전트)

> **이 챕터 한 줄 요약**
> RLHF의 **보상모델 구축(쌍대비교 → Bradley-Terry → KL 정규화)**을 마무리하고, LLM을 두뇌로 삼아 **현실 작업을 수행하는 에이전트**(멀티모달 이해, 도구 사용, 코드 어시스턴트)로 확장한다.

---

## 1. (심화) RLHF 보상 모델 만들기

> 8장에서 본 RLHF의 3단계 중 **보상 모델 학습**을 수식·디테일로 깊이 본다.

### 왜 쌍대비교(Pairwise Comparison)인가 — 핵심
- 보상 모델의 목표: 인간 피드백 기반으로 LLM 출력 품질을 **점수화(scoring)**
- **절대 점수(1~10)를 직접 매기면?** → **평가자마다 절대 점수가 매우 비일관적**
- **해법**: 사람은 **절대 평가보다 상대 평가(둘 중 뭐가 나은가)를 더 잘한다**
- **Preference data** 구성: (prompt, **preferred/winning 응답**, **dispreferred/losing 응답**)

### 보상 모델 셋업 & 학습
- **셋업**: **마지막 토큰 표현에 linear layer**를 붙여 **스칼라 출력**을 학습
- **목적함수**: **Bradley-Terry 쌍대비교** — winning 응답의 보상이 losing 응답보다 높도록 학습

### 보상을 LLM 최적화에 사용 + 그 위험
- 학습된 보상 모델 = **인간 판단의 대리(proxy)**. LLM(정책)이 생성한 응답의 보상을 최대화
- **그런데 보상 모델이 불완전하다면?** 보상 모델은 진짜 인간 선호의 **근사일 뿐**(노이즈·OOD 일반화 약함). 순진하게 보상만 최대화하면:
  - **Reward hacking(보상 모델 결함 악용)**: 실제 바람직한 행동 없이 높은 보상만 얻는 법을 학습
  - **Mode collapse**: 고보상의 좁은 출력 분포로 수렴 → 다양성·일반화 상실
  - **사전학습 지식 상실**: 과최적화로 문법·사실성 등 초기 모델의 바람직한 속성을 망각

### 정규화된 보상 최적화 (Regularized Reward Optimization) — 시험 포인트
> **핵심**: **초기 SFT 체크포인트에서 너무 멀어지는 것에 패널티**를 부여한다.
> 목적 = (보상 최대화) − (초기 SFT 모델에서의 이탈). 이 이탈 패널티는 기댓값으로 **KL divergence**로 알려져 있다(하이퍼파라미터로 강도 조절).

### RL로 최적화하는 이유
- 지도 데이터가 없음(보상 모델만 있음) + 보상에 이끌려 **새 생성 탐색** 장려
- **정책 경사법**(REINFORCE 등): 기대 보상이 커지는 방향으로 정책(LLM) 조정

## 2. 언어 에이전트(Language Agents) 개요 — 챕터 핵심

> **정의**: **자연어를 인터페이스로** 사용자와 상호작용하며 **현실 세계 작업을 실행**하는 시스템. **LLM이 그 기반(foundation)**.

LLM이 에이전트의 토대가 되는 3가지 능력:
- **자연어 이해(NLU)**: 사용자 텍스트 입력 해석
- **자연어 생성(NLG)**: 적절한 응답/행동 생성
- **추론(Reasoning)**: 다단계 추론·문제해결·의사결정

에이전트 예시:
- **가상 비서**: 명령 이해 후 작업 수행(리마인더, 음악 재생, 스마트홈 제어)
- **코드 에이전트**: 코드 스니펫 생성, 개선 제안, 코드 설명
- **비즈니스 운영**: 고수준 목표("마케팅 캠페인 만들기")를 분해 → 정보 검색·종합 → **외부 API/도구와 상호작용하며 자율 실행**

> **현실 사례**: Claude 3.5의 **Computer Use**, 온라인 쇼핑 에이전트 **WebShop**.

## 3. 멀티모달 LLM (Multimodal LLMs)

> **정의**: 텍스트·이미지·오디오·비디오 등 **여러 유형의 데이터를 처리·이해** → 더 포괄적이고 맥락이 풍부한 이해·생성.

- **멀티모달 입력 처리(흔함)**: 이미지 내용 이해, 음성 전사·해석, 비디오 분석, 센서 데이터 통합
- **멀티모달 출력 생성(덜 흔함)**: 텍스트→이미지 생성, 음성→텍스트, 설명→음악 생성

### 아키텍처와 융합(Fusion) — 핵심
- **모달리티별 인코더**(vision/audio/video) 필요, 보통 **LLM이 강력한 base**
- **Early fusion**: 처리 **전에** 서로 다른 모달의 **raw 입력을 결합**
- **Late fusion**: 각 모달을 **따로 처리 후** 표현을 **나중에 결합**
- **데이터셋**: 서로 다른 모달의 **짝지어진(paired) 예시**가 필요 → 모달 간 관계 학습

### Visual Instruction Tuning & LLaVA — 시험 포인트
- **목표**: 시각+텍스트 정보를 모두 다루는 작업의 **지시를 따르도록** 멀티모달 LLM 파인튜닝
- **LLaVA** (Large Language and Vision Assistant): **사전학습 비전 인코더(CLIP) + LLM(Llama)** 결합
- **아키텍처 핵심**: **projection matrix $W$**를 학습해 **이미지 표현 $Z_v$ → 텍스트 임베딩 $H_v$**로 변환 → **시각 토큰 $H_v$와 텍스트 토큰 $H_q$를 concat**해 모델 입력으로. (최신 멀티모달 Llama에도 채택)

## 4. 도구 사용 (Tool Usage)

> **동기**: 많은 작업 수행에는 **외부 도구**(계산기, 캘린더, 검색엔진) 접근이 필요하다.

### Toolformer — 핵심
> LM이 **다양한 도구를 사용하도록 학습**하고, **언제·어떤 도구를 어떻게 쓸지 자동으로 결정**.

고려하는 도구 유형: **QA 시스템, 계산기(Calculator), 기계번역, Wikipedia 검색**.

### 학습 방식: In-context Learning + 필터링
- **In-context로 도구 학습**: 문맥에 **예시 API 호출**을 주면 LLM이 새 데이터에 대한 API 호출을 생성
- **API 호출 필터링(중요)**: 어떤 API 호출은 작업에 도움이 되고 어떤 건 아님
  - **유익한 API 호출은 보통 이후 토큰 생성의 loss를 줄인다**
  - → **loss를 줄이지 못하는 API 호출은 필터링**해서 학습 데이터에서 제거
- **규모 의존성**: **큰 모델일수록 도구를 적절히 사용하는 법을 더 잘 학습**(Wikipedia 검색·계산기·QA 모두)

> **시험 포인트**: Toolformer의 자기지도 라벨링 트릭 = "**해당 API 호출이 미래 토큰의 loss를 줄였는가**"로 유용성을 판단해 필터링.

## 5. 코드 어시스턴트 (Code Assistant)

- 대표 제품: **GitHub Copilot**, **Cursor**

### Code Infilling (코드 채워넣기) — 핵심
> **동기**: 코드는 좌→우 한 번에 쓰이지 않고 **반복적으로 편집·수정**된다. → LLM이 **좌→우 생성**과 **편집(마스킹 후 채우기) 모두** 가능해야 한다.

### InCoder — Causal Masking 기법
- **학습**: 학습 문서에서 **여러 코드 span을 샘플링** → 그 span들을 **문서 끝으로 이동**하고 원래 위치를 **special mask token**으로 표시 → LLM이 마스킹된 전체 문서를 생성하도록 학습 → **양방향 문맥을 조건으로 삽입 텍스트 생성**을 학습
- **추론(편집)**: 원하는 위치에 mask token을 삽입하면 모델이 채울 내용을 생성 → 다양한 코드 편집 가능

### SWE-Bench — 코드 에이전트 평가 — 시험 포인트
> 실제 Python 레포의 **GitHub 이슈를 병합된 PR 솔루션과 연결**해 태스크 인스턴스를 수집. 모델에게 **이슈 텍스트 + 코드베이스 스냅샷**을 주면, 모델은 **패치(patch)를 생성**하고 이를 **실제 테스트로 평가**한다.

→ 단순 코드 생성이 아니라 **실제 소프트웨어 엔지니어링 능력**을 측정하는 벤치마크. (성능은 계속 빠르게 향상 중)

## 핵심 용어 정리 (빠른 복습)

| 용어 | 한 줄 정의 |
|---|---|
| **Pairwise comparison** | 절대점수 대신 상대 선호로 보상 데이터 구성 |
| **Bradley-Terry** | winning > losing이 되도록 보상모델 학습 |
| **Reward hacking / Mode collapse** | 보상 악용 / 좁은 분포 수렴(과최적화 부작용) |
| **KL 정규화** | 초기 SFT 모델에서 이탈 시 패널티 |
| **Language agent** | 자연어로 현실 작업을 실행하는 LLM 기반 시스템 |
| **Early / Late fusion** | raw 입력 단계 결합 / 표현 단계 결합 |
| **LLaVA** | CLIP 비전 인코더 + LLM, projection으로 시각→텍스트 임베딩 |
| **Toolformer** | 언제·어떤 도구 쓸지 자동 결정, loss 감소로 호출 필터링 |
| **Code infilling / InCoder** | 양방향 문맥 기반 코드 삽입·편집 (causal masking) |
| **SWE-Bench** | 실제 GitHub 이슈→패치 생성을 테스트로 평가 |
