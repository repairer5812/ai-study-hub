# 🌟 10차시 — 우선순위 큐와 히프(Heap): 개념·배열 저장·삽입(Up-heap)·삭제(Down-heap)

> **핵심 한 줄 요약**
> **힙(Heap)** = "부모 ≥ 자식(또는 부모 ≤ 자식)" 규칙을 만족하는 **완전 이진 트리(Complete Binary Tree)**. 모양이 꽉 차므로 **배열(1-인덱스)** 로 저장 → 부모 $\lfloor i/2 \rfloor$, 왼쪽 자식 $2i$, 오른쪽 자식 $2i+1$. **삽입**은 마지막 빈자리에 넣고 부모와 비교하며 **위로(Up-heap)**, **삭제**는 항상 **루트(최댓값)** 를 빼고 마지막 노드를 올린 뒤 큰 자식과 **아래로(Down-heap)** 교환. 둘 다 $O(\log N)$. **우선순위 큐(Priority Queue)** 의 표준 구현. **이 차시 연습문제(21,12,33,…)는 교수님이 "기말고사에 그대로 나온다"고 직접 예고한 핵심 출제 영역.**

---

## 🎯 10차시 핵심 출제 포인트 프리뷰 🌟

### ⭐ 핵심 출제 ①: 연습문제 = 기말고사 문제 그 자체
> 🗣️ **교수님 강조**: "이게 바로 여러분들이 기말고사 시험에서 푸실 문제입니다." (데이터 = 21, 12, 33, 14, 25, 36, 7, 28, 39, 10)
- 같은 데이터로 **① BST 구성 → ② 4가지 탐색 → ③ Max Heap 구성 → ④ 루트 삭제 재구성**까지 직접 손으로 그려보는 것이 이번 시험 대비의 핵심.

### ⭐ 핵심 출제 ②: 힙은 "무조건 완전 이진 트리"
> 🗣️ **교수님 강조**: "힙을 만들 때는 **무조건 완전 이진 트리**를 만들어야 한다는 생각을 꼭 하셔야 돼요!"
- 삽입 위치는 값과 무관하게 **마지막 레벨 맨 왼쪽 빈자리부터** 채운다.

### ⭐ 핵심 출제 ③: 힙 삽입의 "값으로 왼쪽 가는 거 아니다" 함정
> 🗣️ **교수님 강조 (한 학생에게 질문하며)**: "값이 작아서 왼쪽으로 가는 것이 아닙니다! **무조건 왼쪽에서 오른쪽으로 빈칸을 채운 뒤**, 부모와 크기를 비교해 위로 올리는(Swap) 방식이에요."
- BST(값 비교로 좌/우 결정)와 힙(자리부터 채우고 위로 올림)의 결정적 차이.

### ⭐ 핵심 출제 ④: BST vs Heap 구분 (지난 시간 예고와 연결)
> 🗣️ **교수님**: "BST는 **L < Root < R** 로 검색용, 힙은 **완전 이진 트리 + 부모-자식 대소**로 우선순위 큐용. 이 둘이 어떻게 다른지가 시험에 나옵니다."

### ⭐ 핵심 출제 ⑤: 배열 인덱스 공식 (1-인덱스)
- 부모 = $\lfloor i/2 \rfloor$, 왼쪽 자식 = $2i$, 오른쪽 자식 = $2i+1$. 9차시 0-인덱스 트리 공식과 **혼동 금지**.

### 📝 시험 형식
- **100% 객관식(선다형)** (전 차시 동일).
- 연습문제 BST/Heap 트레이싱이 변별 핵심.

> 🗣️ **교수님 마무리**: "지난 시간에 일찍 끝낸다 하고 못 끝내서 (한 학생에게) 미안했어요. 기말 전까지 이 연습문제 꼭 **백지에 직접 그려보며** 복습하세요!"

### 1.2 이진 검색 트리(BST) 빠른 복습

- **규칙**: 루트보다 작으면 왼쪽, 크면 오른쪽. 즉 **L < Root < R**.
- **중위 탐색(Inorder) → 오름차순 정렬** 출력.

> 🗣️ **교수님 (한 학생 질문에 칭찬)**: 한 학생이 "나중에 정렬을 오름차순/내림차순 할 것 같다"고 묻자 교수님이 **"맞다"고 칭찬**. → BST 중위 탐색이 곧 오름차순 정렬이라는 핵심을 학생이 미리 캐치한 장면.

- **삭제 3 Case**: 자식 0개(그냥 삭제) / 1개(자식을 끌어올림) / 2개(**왼쪽 서브트리 맨 오른쪽** 또는 **오른쪽 서브트리 맨 왼쪽**으로 대체).

> 💡 **질의응답 (한 학생)**: "26이 제일 가깝고 좌/우 자식이 다 있으면?" → 교수님: 삭제 노드가 18이면 오른쪽 서브트리는 무조건 18보다 큰 값(19 이상)만 와야 하므로 **BST 구조 원칙을 지키는 후계자**를 골라야 한다. 관례상 **오른쪽 서브트리의 맨 왼쪽 노드**를 주로 올린다.

- **성능**: 균형 시 $O(\log N)$, 1·2·3·4처럼 정렬된 채 삽입되면 **편향(Skewed) 트리 → 높이 = $N$ → $O(N)$** (순차 탐색과 동일). → 해결책으로 추후 **AVL 트리** 예고.

## 2. 힙(Heap)의 개념 🌟

![w10 p03](https://repairer5812.github.io/ai-study-hub/assets/images/ds/ds_w10_p03.jpg)

### 2.1 정의

- **힙(Heap)**: 트리 중에서 **부모 노드의 원소 값이 자식 노드의 원소 값보다 항상 큰(또는 작은)** **완전 이진 트리(Complete Binary Tree)**.
- 정확히 말하면 부모 값이 더 큰 경우 **Max Heap(최대 힙)**, 더 작은 경우 **Min Heap(최소 힙)**.
- Max Heap에서 **가장 큰 값은 루트**에, 가장 작은 값들은 리프 노드 중에 있게 된다.

> 🗣️ **교수님 강조**: "힙을 만들 때는 **무조건 완전 이진 트리**를 만들어야 한다는 생각을 꼭 하셔야 돼요!"

### 2.2 Max Heap vs Min Heap

<td>루트</td>
</tr>
<tr>
<td>**Max Heap (최대 힙)**</td>

> 💡 **출제 포인트**: 힙은 **부모-자식 간 대소**만 정해질 뿐, **형제(좌·우) 간 대소는 정해지지 않는다.** 이것이 "중위 탐색하면 정렬되는" BST와의 결정적 차이.

### 2.3 자료구조 선언 (배열 기반)

힙은 중간에 빈 노드가 없는 완전 이진 트리이므로, 연결 리스트보다 **배열(Array) 정적 구현**이 훨씬 효율적이다.

```c
#define MAX_ELEMENTS 200
#define HEAP_FULL(n)  (n == MAX_ELEMENTS - 1)
#define HEAP_EMPTY(n) (!n)

typedef struct {
    int key;
    /* other field */
} element;

element heap[MAX_ELEMENTS];
int n = 0;   // 현재 힙에 저장된 원소 수
```

## 3. 힙의 배열 저장과 인덱스 공식 🌟

![w10 p04](https://repairer5812.github.io/ai-study-hub/assets/images/ds/ds_w10_p04.jpg)

완전 이진 트리를 **레벨 순서(위→아래, 왼→오)** 로 배열에 차곡차곡 담는다. **첨자는 1부터** 시작한다고 가정한다.

> 예시 트리(슬라이드): 루트 20 → 자식 15, 2 → 15의 자식 14, 10. 배열로는 `[1]=20, [2]=15, [3]=2, [4]=14, [5]=10`, 이후는 비어 있음.

## 4. 힙의 노드 삽입 (Insertion = Up-heap / Adjust) 🌟

![w10 p05](https://repairer5812.github.io/ai-study-hub/assets/images/ds/ds_w10_p05.jpg)

### 4.1 삽입 절차

1. **삽입 위치는 이미 정해져 있다**: 완전 이진 트리 형태를 유지하려고 **마지막 레벨의 맨 오른쪽 다음 빈자리**(왼→오 순서)에 새 노드를 넣는다. → 배열로는 `n`을 1 증가시킨 `heap[++n]` 자리.
2. **새 노드와 부모를 비교**: 부모(`heap[i/2]`)가 더 작으면(Max Heap 기준) 두 값을 **교환(Swap)**.
3. **루트에 도달하거나 부모가 더 클 때까지** 위로 올라가며 2를 반복. → 이를 **Up-heap(상향식 재구성)** 이라 한다.

> 🗣️ **교수님 강조**: "값이 작아서 왼쪽으로 가는 게 아니에요. **무조건 빈칸부터 채우고**, 부모랑 비교해서 크면 위로 끌어올리는 겁니다."

### 4.2 슬라이드 예시 (트리 [20,15,2,14,10] 기준)

- **(c) 5 삽입**: 마지막 빈자리 `[6]`에 5 → 부모 `[3]=2`보다 큼 → 5와 2 교환. 결과 배열 `[20,15,5,14,10,2]`.
- **(d) 21 삽입**: 다시 빈자리 `[7]`에 21 → 부모 `[3]=5`보다 큼 → 교환 → 또 부모 `[1]=20`보다 큼 → 교환 → **21이 루트**. 결과 `[21,15,20,14,10,2,5]`.

### 4.3 시간 복잡도

- 트리의 높이 $h$만큼만 위로 올라가므로 **삽입 = $O(h) = O(\log N)$**.
- $h$ = 트리의 깊이 = $\log_2 N + 1$.
- $N$개 데이터를 모두 삽입해 힙을 구성하면 **$O(N \log N)$**.

### 4.4 삽입 알고리즘 (C)

![w10 p06](https://repairer5812.github.io/ai-study-hub/assets/images/ds/ds_w10_p06.jpg)

```c
/* 힙에 데이터를 삽입하는 함수 (Max Heap) */
void insert_max_heap(element item, int *n) {
    int i;
    if (HEAP_FULL(*n)) {
        fprintf(stderr, "The heap is full.\n");
        exit(1);
    }
    i = ++(*n);                                  // 마지막 빈자리
    while ((i != 1) && (item.key > heap[i/2].key)) {
        heap[i] = heap[i/2];                     // 부모를 끌어내림
        i /= 2;                                  // 한 칸 위로
    }
    heap[i] = item;                              // 최종 위치에 삽입
}
```

> 💡 **코드 트레이싱 포인트**: 실제 값 교환(swap) 대신, **부모를 아래로 복사하며 자리를 비워두고** 마지막에 `item`을 한 번만 넣는 최적화 패턴. 루프 조건은 `i != 1`(루트 아님) **그리고** `item.key > heap[i/2].key`(부모보다 큼).

## 5. 힙의 노드 삭제 (Deletion = Down-heap / Adjust) 🌟

![w10 p07](https://repairer5812.github.io/ai-study-hub/assets/images/ds/ds_w10_p07.jpg)

### 5.1 삭제 절차

힙에서 **삭제는 항상 루트(Max Heap이면 최댓값)만** 한다. 삭제 후에도 완전 이진 트리가 유지되도록 재구성한다.

1. **루트 노드를 삭제(반환)** 한다.
2. **마지막 레벨의 맨 마지막 노드**를 뽑아 **빈 루트 자리**에 올려놓는다.
3. 새 루트와 **왼쪽·오른쪽 자식 중 더 큰 값**을 비교해, 더 큰 자식과 자리를 **교환**하며 아래로 내려간다. (왼·오 두 값 중 큰 쪽이 그 서브트리에서 가장 큰 값이므로)
4. **자신보다 큰 자식이 없을 때까지** 반복. → 이를 **Down-heap(하향식 재구성)** 이라 한다.

> 💡 **출제 포인트**: 올라온 노드는 **둘 중 더 큰 자식**과 교환해야 한다. 작은 자식과 바꾸면 그 자식이 다른 형제보다 작아져 힙 규칙이 깨진다.

### 5.2 슬라이드 예시 (트리 [20,15,2,14,10])

![w10 p08](https://repairer5812.github.io/ai-study-hub/assets/images/ds/ds_w10_p08.jpg)

- **(a) 20 삭제**: 루트 20을 빼고 반환.
- **(b) 10을 루트로 이동**: 마지막 노드 `[5]=10`을 루트로 올림 → 트리 `[10,15,2,14]`.
- **(c) 재구성(Down-heap)**: 루트 10의 자식은 15, 2 → 더 큰 15와 교환 → `[15,10,2,14]` → 10의 자식 14 → 더 큼 → 교환 → 최종 `[15,14,2,10]`. (슬라이드 (c) 최종 결과: 루트 15, 자식 14·2, 14의 자식 10)

### 5.3 시간 복잡도

- 트리의 높이만큼 내려가므로 **삭제 = $O(h) = O(\log N)$**.

### 5.4 삭제 알고리즘 (C)

![w10 p09](https://repairer5812.github.io/ai-study-hub/assets/images/ds/ds_w10_p09.jpg)

```c
/* 힙에서 데이터를 삭제하는 함수 (Max Heap) */
element delete_max_heap(int *n) {
    int parent, child;
    element item, temp;
    if (HEAP_EMPTY(*n)) {
        fprintf(stderr, "The heap is empty.\n");
        exit(1);
    }
    item = heap[1];            // 삭제할 루트(최댓값) 반환용
    temp = heap[(*n)--];       // 마지막 노드를 temp에 빼고 n 감소
    parent = 1; child = 2;
    while (child <= *n) {
        // 더 큰 자식 선택
        if ((child < *n) && (heap[child].key < heap[child+1].key))
            child++;
        if (temp.key >= heap[child].key) break;   // 제자리 찾음
        heap[parent] = heap[child];               // 큰 자식을 위로
        parent = child;
        child *= 2;                               // 한 레벨 아래로
    }
    heap[parent] = temp;       // temp를 최종 위치에 안착
    return item;
}
```

> 💡 **코드 트레이싱 포인트**: `child < *n` 조건은 **오른쪽 자식이 존재할 때만** 좌·우를 비교하기 위한 경계 검사. `temp.key >= heap[child].key`이면 더 내려갈 필요 없이 break.

## 6. 우선순위 큐(Priority Queue)와 힙

> 🗣️ **교수님**: "우선순위가 **가장 높은(값이 가장 큰)** 프로세스를 먼저 빼서 처리할 때 힙 구조가 완벽하게 들어맞아요. 가장 낮은 것부터 처리하려면 **Min Heap**을 쓰면 됩니다."

- **우선순위 큐**: 들어온 순서(FIFO)가 아니라 **우선순위가 높은 원소가 먼저 나가는** 추상 자료형.
- **힙 = 우선순위 큐의 표준 구현체**: 최댓값(또는 최솟값)을 $O(1)$에 확인하고 $O(\log N)$에 꺼낼 수 있다.
- 활용: OS 프로세스 스케줄링, 다익스트라 최단 경로, 허프만 코딩, 힙 정렬(Heap Sort).

## 🎯 10차시 최종 암기 체크리스트

### 힙 개념
- [ ] 힙 = "부모-자식 대소 규칙"을 만족하는 **완전 이진 트리**
- [ ] Max Heap: 부모 ≥ 자식, 루트 = 최댓값 / Min Heap: 부모 ≤ 자식, 루트 = 최솟값
- [ ] 형제(좌·우) 간 대소는 **정해지지 않음** (BST와 결정적 차이)
- [ ] 완전 이진 트리라 **배열(1-인덱스) 정적 구현**이 효율적

### 배열 인덱스 공식 (1-인덱스) 🌟
- [ ] 부모 = $\lfloor i/2 \rfloor$
- [ ] 왼쪽 자식 = $2i$
- [ ] 오른쪽 자식 = $2i+1$
- [ ] 9차시 0-인덱스 공식($2i+1$, $2i+2$, $\lfloor(i-1)/2\rfloor$)과 혼동 금지

### 삽입 (Up-heap) 🌟
- [ ] **마지막 레벨 맨 왼쪽 빈자리부터** 채움 (값 무관)
- [ ] 부모와 비교 → 부모가 작으면 교환 → 루트/부모가 클 때까지 위로
- [ ] 삽입 = $O(\log N)$, 전체 구성 = $O(N \log N)$
- [ ] `insert_max_heap`: `i = ++(*n)`, `while(i!=1 && item.key > heap[i/2].key)`

### 삭제 (Down-heap) 🌟
- [ ] 삭제는 **항상 루트(최댓값)** 만
- [ ] 마지막 노드를 루트로 올린 뒤, **더 큰 자식**과 교환하며 아래로
- [ ] 삭제 = $O(\log N)$
- [ ] `delete_max_heap`: 큰 자식 선택(`heap[child]<heap[child+1]`) → `temp.key>=heap[child]` break

### 우선순위 큐
- [ ] 힙 = 우선순위 큐의 표준 구현
- [ ] 최댓값 확인 $O(1)$, 꺼내기 $O(\log N)$
- [ ] 가장 낮은 우선순위부터 → Min Heap

### BST vs Heap 🌟 [기말 변별 핵심]
- [ ] BST: L<Root<R, 검색용, 중위=오름차순 / Heap: 완전 이진, 우선순위 큐
- [ ] BST 삽입은 값 비교로 좌/우 / Heap 삽입은 자리부터 채우고 Up-heap

- [ ] BST 중위 = 7,10,12,14,21,25,28,33,36,39 (오름차순)
- [ ] Max Heap = [39,36,33,28,14,21,7,12,25,10], 루트 삭제 후 = [36,28,33,25,14,21,7,12,10]
