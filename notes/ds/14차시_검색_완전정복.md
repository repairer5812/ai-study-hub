# 🌟 14차시 — 검색(Search) 완전 정복 [기말]

> **범위**: 검색의 개념·성능 평가 → 선형 검색(O(N)) → 이진 검색(O(log N)) → 해싱(해시함수·충돌·오버플로우 해결 4종) → 이진 탐색 트리(검색·삽입·삭제 3 CASE) → AVL 트리(BF·회전 4종) → 2-3트리·B-트리·B+트리.
>
> 💡 **출제 1순위**: 이진 검색 n=2ᵏ → k=log₂N 유도 · 해싱은 비교 없이 O(1) 접근(검색 중 최고속) · 충돌 해결 4종(Linear/Quadratic Probing·Double Hashing·Chaining) · BST 삭제 3 CASE · AVL의 BF(T)∈{−1,0,1}과 회전 4종(LL·RR·RL·LR) · BST 최악(경사 트리)=순차 탐색 O(N).

---

## 1. 선형 검색 (Sequential / Linear Search)

### 1-1. 개념
- **선형 검색**(선형 탐색·순차 탐색): 주어진 데이터에서 **키 값으로 데이터를 찾는** 과정. 검색 방법 중 **가장 간단**하다.
- 정렬돼 있지 않아도 되며, 배열의 처음부터 끝까지 차례로 `find_key`와 비교한다.

```c
/* 선형검색 알고리즘 — 배열 keys[]에서 find_key와 일치하는 것을 찾는다. */
int sequential_search(int keys[], int find_key, int n)
{
    int i = 0;
    while (i <= n)
    {
        i++;
        if (keys[i] == find_key) return(i);
    }
    return(0);
}
```

### 1-2. 성능 분석
- 프로그램은 key 값을 데이터와 **비교**한다. 운이 좋으면 1번에 찾지만, **최악**(맨 마지막에 있거나 데이터가 없는 경우)은 **N개를 모두 비교**해야 한다.
- 평균을 내면 **N/2번 비교** → 효율도(빅오)로는 **O(N)**.
- ⚠️ **주의**: 데이터가 1000~10000개면 비교적 빠르지만, **1백만·1억 개**면 선형 검색은 사용하기 어렵다.
- 🗣️ **교수님 코멘트**: 다음부터 나오는 검색 알고리즘들은 모두 O(N)보다 효율적이라 대략 **O(log N)** 정도의 시간이 걸린다(선형 검색을 비교 기준점으로 잡고 출발).

## 2. 이진 검색 (Binary Search)

### 2-1. 개념
- 💡 **이진 검색은 반드시 정렬된 데이터에서만 사용**한다. (정렬이 검색을 빠르게 하기 위한 전처리라는 13차시 명제와 직결.)
- 1~10,000이 정렬된 리스트에서 5001을 찾을 때, 첫 데이터부터 하나씩 비교하는 것보다 **가운데 데이터부터 비교**하는 것이 훨씬 빠르다.
- **원리**: 찾는 값을 **리스트 가운데(mid) 값과 비교** → 찾는 값이 가운데보다 **크면 오른쪽 반**, **작으면 왼쪽 반**만 다시 비교. 매번 비교할 때마다 대상 리스트를 **½로 줄인다**.

```
예) [9 15 16 19 21 39 51 65 76 85 99]에서 Key(65) 검색
  1단계: Key(65)와 39 비교 → 크므로 오른쪽 [51 65 76 85 99]
  2단계: Key(65)와 76 비교 → 작으므로 왼쪽 [51 65]
  …정렬돼 있으므로 반씩 잘라가며 (큰 쪽/작은 쪽을) 택한다.
```

### 2-2. 알고리즘
```c
BinarySearch(int list[], int n, int key) {
    left = 0;
    right = n - 1;
    while (left <= right)
    {
        mid = (left + right) / 2;
        if (list[mid] == key) return mid;
        else if (list[mid] < key) left = mid + 1;   // 오른쪽 반
        else right = mid - 1;                        // 왼쪽 반
    }
    return -1;   // 못 찾음
}
```
- ⚠️ **경계 갱신**: `list[mid] < key`면 `left = mid + 1`, 아니면 `right = mid - 1`. mid는 매 반복마다 `(left+right)/2`로 다시 계산한다.

### 2-3. 성능 분석 (💡 출제 핵심)
- **while 문 반복 횟수**가 곧 이진 검색의 시간이다. 찾으면 1번에 끝나지만, 못 찾으면 리스트가 1개가 될 때까지 반을 대상으로 비교한다.
  - 비교 대상 개수 변화: **N → N/2 → N/4 → N/8 → …**
- **유도**: N = 2ᵏ라 가정하면 데이터 개수는 **2ᵏ → 2ᵏ⁻¹ → 2ᵏ⁻² → … → 2⁰** 으로 매 반복마다 ½로 변한다.
  - 데이터가 1개가 될 때까지 반복하므로 **k번 반복**.
  - N = 2ᵏ 양변에 밑이 2인 log → **log₂N = k** → 따라서 **k번 반복**.
- **결론**: 이진 검색의 복잡도는 **O(log N)**.

| 비교 | 선형 검색 | 이진 검색 |
|---|---|---|
| 정렬 필요 | 불필요 | **필수** |
| 평균 비교 | N/2 | log₂N |
| 복잡도 | O(N) | **O(log N)** |

## 3. 해싱 (Hashing)

### 3-1. 개념
- **해싱**: 찾으려는 **키 값을 조작(연산)해 데이터를 바로 찾는** 방법.
- 🗣️ **예시(교수님)**: 키 값을 제곱해 끝 2자리 위치에 저장한다면, 데이터 123은 123×123=**15,129** → 끝 두 자리 **29** → 키가 123이면 데이터가 **X[29]** 에 있음을 바로 안다.
- 💡 **검색 중 가장 빠름**: 선형(평균 N/2)·이진(log N)과 달리, 해싱은 **비교도 없이 바로** 찾을 수 있다 → 검색 중 최고속.
- **해시함수 f(x) = α**: 키 값(identifier) x를 해시 테이블(hash table) 주소 α로 사상(mapping).

### 3-2. 해싱 용어
- **해시 테이블(hash table)**: **M개의 버킷(bucket)** 으로 구성. 원소는 ht[0], ht[1], …, ht[M−1]. 하나의 버킷에 **s개의 슬롯(slot)** 이 가능.
- **충돌(collision)**: 서로 다른 두 탐색키 k1, k2에 대해 **h(k1) = h(k2)** 인 경우.
- **오버플로우(overflow)**: **충돌이 버킷의 슬롯 수보다 많이** 발생하는 것. ⚠️ **오버플로우 해결 방법은 반드시 필요**.
- **적재밀도(loading density)**: **저장된 항목 수 ÷ 해시 테이블 버킷 수 = n / M**.

```
예) 해시함수 = 키의 첫 글자 순서, 슬롯 2개(slot0, slot1)
  입력: array, binary, bubble, file, digit, direct, zero, bucket
  버킷0: array        버킷1: binary | bubble   버킷3: digit | direct …
  → "bucket"은 버킷1이 이미 꽉 차(slot 2개 초과) overflow로 저장 불가능!
```

### 3-3. 좋은 해시함수의 조건
- **충돌이 적어야** 한다.
- 해시함수 값이 해시 테이블 **주소 영역 내에서 고르게 분포**돼야 한다.
- **계산이 빨라야** 한다.

### 3-4. 해시함수의 종류
- **제산 함수(division)**: **h(k) = k mod M**. 💡 해시 테이블 크기 **M은 소수(prime number)** 로 선택(고른 분포·충돌 감소).
- **폴딩 함수(folding)**: 탐색키를 몇 부분으로 나눠 더한다. **이동 폴딩(shift folding)** 과 **경계 폴딩(boundary folding)** 이 있다.
  - 예) 키 123 203 241 112 20 → 이동폴딩 123+203+241+112+20 = **699** / 경계폴딩(번갈아 뒤집기) 123+**302**+241+**211**+20 = **897**.
- **중간제곱 함수(mid-square)**: 탐색키를 **제곱**한 뒤 **중간의 몇 비트**를 취해 해시 주소 생성.
- **비트추출 함수**: 탐색키를 **이진수로 간주**, 임의 위치의 **k개 비트**를 해시 주소로 사용.
- **숫자 분석 방법(digit analysis)**: 키 중 **편중되지 않은 수들**을 테이블 크기에 맞게 조합해 사용.

### 3-5. 오버플로우 해결 방법 (💡 출제 단골)
오버플로우 해결은 크게 **개방 주소법(Open Addressing)** 계열 3종과 **체이닝**으로 나뉜다.

#### (1) Linear Probing (선형 조사법)
- 충돌이 ht[k]에서 나면 **ht[k+1]이 비었는지** 조사. 비어 있지 않으면 ht[k+2]… **빈 공간이 나올 때까지** 조사.
- 테이블 **끝에 도달하면 다시 처음부터** 조사. **시작했던 곳으로 되돌아오면** 테이블이 가득 찬 것으로 판단.
- 조사 위치: **h(k), h(k)+1, h(k)+2, …**
```
예) h(k)=k mod 7, 입력 (8,1,9,6,13)
  8 → 8 mod 7=1 (저장)
  1 → 1 mod 7=1 (충돌) → (1+1) mod 7=2 (저장)
  9 → 9 mod 7=2 (충돌) → (9+1) mod 7=3 (저장)
  6 → 6 mod 7=6 (저장)
 13 → 13 mod 7=6 (충돌) → (13+1) mod 7=0 (저장)
```

#### (2) Quadratic Probing (이차 조사법)
- 선형 조사법과 유사하지만 다음 조사 위치를 **제곱 간격**으로: **(h(k) + inc×inc) mod M**, inc = 0, 1, …, M−1.
- 조사 위치: **h(k), h(k)+1, h(k)+4, …** (1², 2², …)

#### (3) Double Hashing (이중 해싱)
- 오버플로우 발생 시 **원 해시함수와 다른 별개의 해시함수**로 보폭(step)을 정한다: **step = C − (k mod C)**.
- 조사 위치: **h(k), h(k)+step, h(k)+2×step, …**
```
예) h(k)=k mod 7, step=5−(k mod 5), 입력 (8,1,9,6,13)
  8 → 1 (저장)
  1 → 1 (충돌) → (1 + (5−1 mod 5)) mod 7 = (1+4) mod 7 = 5 (저장)
  9 → 2 (저장)
  6 → 6 (저장)
 13 → 6 (충돌) → (6 + (5−13 mod 5)) mod 7 = (6+2) mod 7 = 1 (또 충돌)
     → (6 + 2×2) mod 7 = 3 (저장)
```

#### (4) Chaining (체이닝)
- 오버플로우를 **연결 리스트(linked list)** 로 해결. 각 버킷에 **고정된 슬롯이 할당돼 있지 않다**.
- 각 버킷에 **삽입·삭제가 용이한 연결 리스트**를 할당. 버킷 내에서는 **연결 리스트 순차 탐색**.
```
예) h(k)=k mod 7, 입력 (8,1,9,6,13)
  버킷1 → [8] → [1]      버킷2 → [9]
  버킷6 → [6] → [13]     (충돌 시 새 노드 생성해 연결)
```

## 4. 이진 탐색 트리 (Binary Search Tree, BST)

### 4-1. 개념
- **탐색 작업을 효율적으로** 하기 위한 자료구조.
- 💡 **정의**: **key(왼쪽 서브트리) ≤ key(루트 노드) ≤ key(오른쪽 서브트리)**. (루트보다 작은 값은 왼쪽, 큰 값은 오른쪽.)
- 💡 **이진 탐색 트리를 중위 순회(inorder)하면 오름차순 정렬된 값**을 얻는다.

### 4-2. BST에서의 검색
- 비교 결과가 **같으면** 탐색 성공 종료.
- 키가 루트보다 **작으면** 루트의 **왼쪽 자식**을 기준으로 다시 시작.
- 키가 루트보다 **크면** 루트의 **오른쪽 자식**을 기준으로 다시 시작.
```c
// 순환(재귀) 검색 함수
TreeNode *search(TreeNode *node, int key) {
    if (node == NULL) return NULL;
    if (key == node->key) return node;          // (1) 성공
    else if (key < node->key)
        return search(node->left, key);          // (2) 왼쪽
    else
        return search(node->right, key);         // (3) 오른쪽
}
```
- 반복(iterative) 버전도 동일 논리(`while(node!=NULL)`로 left/right 이동, 실패 시 NULL 반환).

### 4-3. 노드 삽입
- ⚠️ **삽입 전 먼저 탐색을 수행**한다. **탐색에 실패한 그 위치**가 곧 새 노드를 삽입하는 자리.
- 예) 9 삽입 → 9 탐색을 하다 NULL(빈 자리)에 도달 → 그 자리에 9를 단다.
- 같은 key가 이미 트리에 있으면 삽입하지 않는다.

### 4-4. 노드 삭제 (💡💡 3가지 CASE — 출제 단골)
| CASE | 상황 | 처리 |
|---|---|---|
| **CASE 1** | 삭제 노드가 **단말(leaf)** | 단말 노드의 **부모를 찾아 연결을 끊는다** |
| **CASE 2** | 삭제 노드가 **서브트리 1개**(왼쪽 또는 오른쪽 하나)만 보유 | 그 노드를 삭제하고 **서브트리를 부모 노드에 붙인다** |
| **CASE 3** | 삭제 노드가 **서브트리 2개** 모두 보유 | **삭제 노드와 가장 비슷한 값**을 가진 노드를 삭제 노드 자리로 가져온다 |
- 🗣️ **CASE 3 보충**: "가장 비슷한 값"은 왼쪽 서브트리의 최댓값(후행 직전값) 또는 오른쪽 서브트리의 최솟값(후행값)이며, 이를 끌어와 BST 정렬 성질을 유지한다.

### 4-5. 성능 분석
- 탐색·삽입·삭제 연산의 시간 복잡도는 **트리의 높이 h에 비례**한다.
- **최선**: 트리가 **균형적**으로 생성 → **h = log₂N** → **O(log N)**.
- ⚠️ **최악**: 한쪽으로 치우친 **경사 이진 트리(skewed)** → **h = N** → **순차 탐색과 시간 복잡도가 같다(O(N))**.

## 5. AVL 트리 (AVL Tree)

### 5-1. 개념
- 💡 **Adelson-Velskii & Landis**가 **1962년** 제안한 트리(이름의 어원).
- **균형 이진 트리(balanced binary tree)**: 모든 노드의 **왼쪽·오른쪽 트리 높이차를 1 이하**로 만든 트리.
- 💡 **평균·최악 모두 O(log₂N)** (BST의 최악 O(N) 문제를 높이 균형으로 극복).
- **높이 균형(height balanced)의 정의**: 트리 T가 비었거나, T_L·T_R(왼쪽·오른쪽 부속 트리)이 각각 높이 균형이고 **|h_L − h_R| ≤ 1** 이면 T는 높이 균형이다.

### 5-2. 균형 인자 (Balance Factor, BF)
- 💡 **BF(T) = h_L − h_R** (왼쪽 트리 높이 − 오른쪽 트리 높이).
- 💡 **AVL 트리의 모든 노드는 BF(T) = −1, 0, 또는 +1**. (이 범위를 벗어나면 균형이 깨진 것.)

### 5-3. AVL 트리의 생성 (회전 4종 — 💡💡 출제 핵심)
- 삽입·삭제로 높이 균형이 깨져 **BF가 +2 또는 −2**가 되면, 깨진 모양에 따라 **회전(rotation)** 으로 균형을 다시 맞춘다.
- **Y**: 새로 삽입된 노드, **A**: Y의 조상으로 **균형 인자가 ±2가 되는 노드**.

| 회전 | 삽입 위치 (Y가 A의 …) | 회전 방향 |
|---|---|---|
| **LL** | **왼쪽의 왼쪽** 부속 트리 | 오른쪽 회전 |
| **RR** | **오른쪽의 오른쪽** 부속 트리 | 왼쪽 회전 |
| **RL** | **오른쪽의 왼쪽** 부속 트리 | 오른쪽-왼쪽 회전 |
| **LR** | **왼쪽의 오른쪽** 부속 트리 | 왼쪽-오른쪽 회전 |

- 💡 **대칭 관계**: **LL과 RR이 대칭(symmetric)**, **LR과 RL이 대칭**.
- **복합 회전 분해**:
  - **RL(A)** = rotate_LL(B)가 반환한 노드를 A의 오른쪽 자식으로 만든 뒤 → rotate_RR(A).
  - **LR(A)** = rotate_RR(B)가 반환한 노드를 A의 왼쪽 자식으로 만든 뒤 → rotate_LL(A).
- **단순 회전 정의**:
  - **rotate_LL(A)**: B의 오른쪽 자식을 A의 왼쪽 자식으로 만들고, A를 B의 오른쪽 자식 노드로 만든다.
  - **rotate_RR(A)**: B의 왼쪽 자식을 A의 오른쪽 자식으로 만들고, A를 B의 왼쪽 자식 노드로 만든다.

### 5-4. 성능 분석
- AVL 트리는 BST의 단점(경사 트리)을 극복해 **높이를 균형**으로 맞춘 것.
- 트리 높이가 **log N**이므로 검색 시간 복잡도도 **O(log N)**.
- 삽입·삭제 시 BF가 깨지면 **±2가 되는 노드를 대상으로 회전**해 균형을 다시 맞춘다.
- 💡 **검색·삽입·삭제의 평균·최악 모두 O(log₂N)**.

## 6. 2-3 트리 · B-트리 · B+트리

### 6-1. 2-3 트리의 개념
- **차수가 2 또는 3인 노드**를 갖는 트리.
- **2-노드**: 이진 탐색 트리처럼 데이터 **k1 하나**와 **자식 2개**.
- **3-노드**: 데이터 **k1, k2 두 개**와 **자식 3개**.
- 💡 **정렬 규칙**:
  - 왼쪽 서브트리 데이터는 모두 **k1보다 작다**.
  - 중간 서브트리 값은 모두 **k1보다 크고 k2보다 작다**.
  - 오른쪽 서브트리 데이터는 모두 **k2보다 크다**.

### 6-2. 2-3 트리의 생성 (노드 분리)
- 노드 추가 예) 빈 노드 → 30 삽입 → 60 삽입(30|60) → 20 삽입(20|30|60, 3개 초과) → **분리**: 중간값 30이 위로 올라가고 20·60이 자식으로.
- **노드 분리 3종**: ① **루트 노드 분리** ② **단말 노드 분리** ③ **비단말 노드 분리**.
  - **루트 분리**: small|middle|large → **middle이 새 루트**, small·large가 좌·우 자식.
  - **단말 분리**: 부모가 2-노드면 middle이 부모로 병합, 부모가 3-노드면 다시 분리 연쇄.

### 6-3. 이진 탐색 트리 vs 2-3(3-way) 트리
- **3-way 트리는 2진 트리보다 높이가 낮다**.
- 💡 2진 탐색 트리는 한 단계 진행할 때 노드 개수가 **반(1/2)** 으로 줄지만, 3-way 트리는 **약 1/3로** 줄어든다 → 더 적은 단계로 탐색.

### 6-4. B-트리의 개념
- m-원 탐색 트리의 성능 향상을 위해 **m을 크게 + 트리를 균형**으로 만든다. **트리 높이에 제한**을 둬 탐색을 효율화한 것이 **B-트리**.
- 💡 **B-트리(m-way 탐색 트리)의 조건**:
  1. 각 노드는 **최대 m개, 최소 ⌈m/2⌉개의 종속 트리**를 갖는다.
  2. **루트 노드는 최소 2개**의 종속 트리를 갖는다.
  3. 모든 **단말 노드는 같은 레벨(서열)** 에 있어야 한다.
  4. 노드의 **키 개수는 종속 트리 개수보다 1개 적으며**, 최소 ⌈m/2⌉−1개, **최대 m−1개**.

### 6-5. B+트리
- **B-Tree**는 한 데이터 검색은 효율적이지만, **모든 데이터를 순회**하려면 모든 노드를 방문해야 해 비효율적. 이를 개선한 것이 **B+Tree**.
- 💡 **B+Tree 특징**:
  - **오직 leaf node에만 데이터를 저장**하고, leaf가 아닌 node에는 **자식 포인터만** 저장.
  - **leaf node끼리 Linked list로 연결**돼 있어 순차 접근(범위 검색)이 빠르다.

## 7. 📊 검색 알고리즘 비교표 (암기)

| 검색 | 평균 | 최악 | 정렬/조건 | 핵심 특징 |
|---|---|---|---|---|
| **선형(순차)** | O(N) | O(N) | 불필요 | 처음부터 끝까지 비교, 평균 N/2회, 가장 단순 |
| **이진** | **O(log N)** | O(log N) | **정렬 필수** | 매번 ½ 축소, n=2ᵏ→k=log₂N |
| **해싱** | **O(1)** | O(N)* | 해시함수 | 비교 없이 바로 접근, 검색 중 최고속, 충돌·오버플로우 처리 필요 |
| **BST** | O(log N) | **O(N)** | — | 중위순회=오름차순, 최악(경사 트리)=순차 탐색 |
| **AVL** | **O(log N)** | **O(log N)** | 높이균형 | BF∈{−1,0,1}, 회전 4종(LL·RR·RL·LR), 평균=최악 |
| **2-3 / B-트리** | O(log N) | O(log N) | 균형·다원 | 노드당 키 2~3(또는 m−1), 높이 낮음, 단말 같은 레벨 |

\* 해싱 최악은 모든 키가 한 버킷에 충돌해 체이닝 리스트를 순차 탐색하는 극단적 경우. 좋은 해시함수·낮은 적재밀도에서는 평균 O(1)에 가깝다.

## 8. ✅ 14차시 최종 암기 체크리스트

- [ ] **선형 검색**: 평균 **N/2** 비교, **O(N)**, 정렬 불필요, 가장 단순
- [ ] **이진 검색**: **정렬 필수**, 매번 ½ 축소, **N=2ᵏ → log₂N=k → O(log N)**
- [ ] 이진 검색 코드: `mid=(left+right)/2`, 작으면 `right=mid−1`·크면 `left=mid+1`
- [ ] **해싱 = 비교 없이 바로 접근**(검색 중 최고속), 예: 123²=15129 → X[29]
- [ ] 해싱 용어: 버킷 M개·슬롯 s개, **충돌 h(k1)=h(k2)**, 오버플로우=슬롯 초과, **적재밀도 n/M**
- [ ] 해시함수: **제산 h(k)=k mod M(M=소수)**·폴딩(이동/경계)·중간제곱·비트추출·숫자분석
- [ ] **오버플로우 4종**: Linear Probing(h+1,+2)·Quadratic(h+1,+4)·**Double Hashing(step=C−(k mod C))**·Chaining(연결 리스트)
- [ ] **BST**: key(좌)≤key(루트)≤key(우), **중위순회=오름차순**
- [ ] **BST 삭제 3 CASE**: ①단말=연결 끊기 ②서브트리 1개=부모에 붙이기 ③서브트리 2개=**가장 비슷한 값** 가져오기
- [ ] **BST 성능**: 최선 h=log₂N → O(log N), **최악 경사 트리 h=N → 순차 탐색과 동일 O(N)**
- [ ] **AVL**: Adelson-Velskii·Landis 1962, **BF(T)=h_L−h_R ∈ {−1,0,1}**, 평균=최악 **O(log N)**
- [ ] **AVL 회전 4종**: LL(왼-왼)·RR(오-오)·RL(오-왼)·LR(왼-오), **LL↔RR·LR↔RL 대칭**, ±2 노드가 회전 대상
- [ ] **2-3트리**: 2-노드(k1·자식2)·3-노드(k1,k2·자식3), 노드 분리(루트/단말/비단말), 3-way는 단계당 **1/3**로 축소
- [ ] **B-트리**: m-way, 노드 최대 m·최소 ⌈m/2⌉ 종속트리, 키 최대 m−1, **단말 같은 레벨**
- [ ] **B+트리**: **leaf에만 데이터**, 내부 노드는 포인터만, **leaf끼리 Linked list** 연결

💪 이진 검색 log 유도 + 해싱 충돌 해결 4종 + BST 삭제 3 CASE + AVL BF·회전 4종 + 경사 트리=순차 탐색만 확실하면 검색 파트는 끝!
